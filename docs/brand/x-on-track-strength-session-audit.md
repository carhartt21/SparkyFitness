Watch set actions use stable set keys and value signatures in the mirrored workout, a persisted Watch outbox, a phone-side account/session/value/completion conflict check, and operation-ID deduplication. The Watch sends one unresolved action at a time and waits for its acknowledgement before sending the next; a failed action can be retried or dismissed. The phone serializes session saves and acknowledges an action only after its server save completes. If the requested completion state is already present but an operation ID was lost across a crash, replay is treated as satisfied without restarting rest. A cached context cannot clear a newly acknowledged action. The Watch target compiles, and the focused active-workout store and autosave suites pass with 270 tests. The internal TestFlight pass confirmed the connected set round trip, offline delivery exactly once, and one final diary session; reconnect ordering and cross-device edit conflicts remain open. Apple Health workout export is not part of this implementation.

Hevy workout-history import now carries an exercise's configured `rest_seconds` into each diary set's `rest_time`, matching the saved-routine import. Invalid or absent rest values remain unset. This mapping is covered by the focused server test; displaying the imported rest interval on a phone remains part of the separate device gate.

Workout and activity form drafts now use a separate local key for each verified server/user pair. A form binds to the identity that loaded it; delayed debounce, background, and unmount saves cannot write into another account after an identity change. Reset and discard clear only that bound draft. Draft storage operations are serialized, so a discard cannot be undone by an earlier autosave that finishes late. The former global `@SessionDraft` value has no recorded owner, so it is preserved on disk for manual recovery but not restored automatically. Six related mobile suites passed 157 tests, plus TypeScript and targeted lint. Draft restoration after a real account/server switch still needs a physical app check.

The CSV preview normalizes mixed CRLF/LF record separators without rewriting line breaks inside quoted workout or exercise notes. A focused parser test covers escaped quotes and a multiline note, and server validation passes. Saved routines still require a separate authorized API sample; a workout-history CSV cannot identify them.

Hevy body measurements with an `updated_at` timestamp now use the person's local day; date-only source values remain unchanged. A timestamp without an offset is skipped rather than assigned a day from the server machine's timezone. Focused tests cover a UTC-to-local midnight crossing and an offset-free timestamp.

If Hevy supplies a measurement but its timestamp is ambiguous or the database write fails, the API sync now reports a partial result and leaves the connection's successful-sync time unchanged. Workout and saved-routine imports still run; the same rule applies to a raw-response replay. User info without a weight or height needs no measurement write and causes no warning.

The Hevy manual-sync date picker now limits completed workouts to its selected inclusive local calendar days. The service fetches all workout pages for an explicit range, so an older chosen window is not cut off by the normal seven-day incremental stop; it filters by the user's timezone before writing. Saved routines still sync through their separate API endpoint, independent of that workout range. Invalid or incomplete ranges return HTTP 400. Focused service and route tests cover the timezone boundary, older-page pagination, routine separation, and range rejection.

Live Hevy sync and raw-response replay now reject malformed individual workout or routine records without discarding valid records from the same page. Rejected items make the sync partial and leave its successful-sync time unchanged, so a later retry remains possible. If an incremental workout page contains a rejected item, the sync checks the remaining pages rather than assuming that the recent-workout window is complete. The focused pagination suite covers mixed valid/malformed pages and this continuation. Saved-routine API shape still awaits an authorized sample.

The [Hevy public API schema](https://api.hevyapp.com/docs/) describes routine exercises, `rest_seconds`, `superset_id`, set types, and `rep_range` in the shape used by the synthetic routine fixture. It documents workout times as ISO 8601 timestamps. The importer now requires an explicit UTC offset for start and end times, so an offset-free value cannot be assigned a day using the server machine's timezone. An invalid start time on an incremental page also forces the remaining pages to be checked and makes the sync partial. This documentation check does not replace a real authorized saved-routine response or live import acceptance.

Client-authored set types now share one accepted-label boundary across grouped diary sessions, saved routines, and workout-plan templates. Blank legacy editor selections become null; accepted labels keep their spelling so editing a stored session does not rename its sets. Unknown labels return HTTP 400 before a route calls its write service. Four focused server suites passed 64 tests, and server, web, and mobile validation passed after the shared request-schema change. This does not rewrite historical rows or replace the physical presentation gate.

The shared set-type menu now labels the canonical `drop` option as “Drop set” and recognizes imported spellings such as `Drop Set`, `Warm-up Set`, and `To Failure` when showing the selected option. Recent-session set summaries display their D/W/F markers using the same classifier. These changes affect presentation; they leave the stored set type unchanged until a person explicitly chooses a menu option. The focused menu and workout-session suites cover this behavior; visual confirmation remains in the physical-device gate.
