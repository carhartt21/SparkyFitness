# X on Track physical-device release gate

This document records tests that require a physical iPhone and paired Apple Watch. No result below is inferred from Jest, Expo prebuild, a simulator, or the prior PersonalBest build. Use synthetic records and keep private health data out of screenshots and logs.

## Build and asset provenance

- [x] Reconstruct light and dark SVG masters from the owner-authorized 320 px [Notion previews](https://app.notion.com/p/3e45fb777c5d81ce9afdfbb0c6e64524), inspect at small size, and export 2048 px PNGs. These are vector redraws, not the missing named originals.
- [x] Build and sign the iOS app, iOS widget, Watch app, Watch widget, and Live Activity extension with the existing team and bundle IDs. Record the EAS or Xcode build ID and the inspected display names.
- [x] Build and sign all five targets with the vector-derived artwork; the final `f2b01a34` IPA below replaces the preview-artwork build.
- [ ] Confirm the signed artifact installs in place over the current development app without removing its synthetic diary, authentication state, or Watch pairing.

## iPhone visual and behavior pass

- [ ] Launcher, Spotlight, app switcher, notification, and tinted icon show the approved X geometry at small size in light and dark appearance.
- [ ] Splash, onboarding, About, settings, permission prompts, notification text, and Live Activity say **X on Track** where the product is named. **Keep getting better.** is used only as brand language, not as a false progress status.
- [ ] Cold launch and sign-in reach the existing server over HTTPS; a saved synthetic food note and workout remain after force-close and reopen.
- [ ] Existing HealthKit and notification permissions survive the in-place upgrade. If the OS re-prompts, record which capability and why.
- [ ] Home, Diary, nutrition quick actions, active workout, rest timer, widgets, and Live Activity remain usable with Dynamic Type, VoiceOver, reduced motion, and dark mode.
- [ ] On Add Food, check the photo, nutrition summary, amount/unit controls, quick portions, and meal/date/time selection in light and dark mode. With a long entry note and the keyboard open, the focused text stays visible and Add Food remains reachable; after saving, the note persists on the entry.
- [ ] Widget installation/registration, tap deep links, and lock-screen or reduced-luminance presentations use the right brand and reveal no sensitive detail by default.

## Paired Apple Watch pass

- [ ] Watch app and Watch widget install as the same product family and show **X on Track** display names and the approved icon in relevant system surfaces.
- [ ] A watch check-in and live workout round-trip through the phone without duplicating records; test offline queue and reconnect once.
- [ ] Rest controls, notifications, and complication links open the expected screen and keep the workout session intact.

## Web, identity, and attribution pass

- [ ] Web tab, PWA install icon, login, navigation, About, and exported filenames show X on Track; narrow and wide layouts remain readable.
- [ ] A new verification email and authenticator setup present X on Track. Existing passkeys and TOTP secrets still authenticate; OS-managed old labels may remain until refreshed.
- [ ] Upstream GitHub/license and policy links are visibly identified as **SparkyFitness upstream** material, not X on Track support or a newly approved X on Track privacy policy.
