### Review corrections

The native review found a real accessibility-text defect in meal settings: the long default-time label consumed the row and hid the meal name/editor. At enlarged text sizes the name/editor and time now stack, and the shared reorder geometry uses the scaled row height. Normal-size time cells have a bounded width, and full labels remain accessible. The focused meal-settings regressions passed after this correction.

The confirmation renders also exposed a food keyboard-accessory label overflowing at the largest text size and fixed-height calendar weekday captions clipping. The accessory now uses the existing short localized Add label while retaining the complete accessible description, and stacks actions when text is enlarged. Calendar captions and day rows grow with the text scale; header arrows retain 44-point targets. Final renders show the complete labels and reachable actions without shrinking accessibility text.

The review harness also needed navigation waits and visible-coordinate handling: a bottom-sheet backdrop's accessible frame includes covered content, and a partly visible date control can report `isHittable` while its center is behind the keyboard. The final flow uses a visible save action and scrolls date controls fully into view. These were harness corrections, not evidence that all backdrop interactions were verified.

### Migration/security and remaining checks

The only schema change is additive `user_meal_visibilities.icon_key`. Standard server startup applies it before the new clients use it. It retains `create_diary_policy` (`can_manage_diary` write; `can_view_reports`/`can_manage_diary` read), while API writes remain scoped to the selected account and owned/system meal. There is no new table, RLS grant, authentication change or rewrite of historical records. [Database/security documentation](../src/developer/database-security-tiers.md#tier-3-delegate-writable-daily-logs--schedules) reflects the actual existing policy. Multi-account authorization was inspected, not exercised with separate authenticated accounts. `db_schema_backup.sql` remains CI-owned.

Additional BLS components are **not** mapped in this batch. The current source adapter exposes core values plus its existing supported micronutrients; retained raw fields do not automatically become display values, and vitamin A remains subject to the published source errata. The UI now displays supported values correctly but cannot manufacture missing source nutrients. A separate source-backed BLS mapping pass is the next improvement if broader live catalogue coverage is needed.
