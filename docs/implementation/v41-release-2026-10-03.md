artwork expansion with the v41 inbox corrections. The earlier v40 correction
commits are included through their existing cherry-picks; they are not merged a
second time. The only merge conflict was the documentation index, resolved by
retaining both records. No open GitHub PRs were reported by the repository API.

change. The feature diffs preserve snapshots, existing permission controls,
unknown nutrients and logging/outbox behavior. The source is suitable for the
owner-authorized internal TestFlight/private-server cycle with the limits below.

## Production preflight and rollout boundaries

Read-only preflight verified the healthy production frontend/API at the recorded
v39 revision `bcb401c4a`, an unchanged migration ledger and **7,140 BLS foods**.
No migration, catalogue replacement, nutrient repair or historical data rewrite
is required. Build the frontend and server from one clean, pushed main revision.
Capture the live image IDs, protected configuration/routing hashes and mounts;
retain them for automatic image rollback. Require a fresh matched encrypted
backup with a verified off-host copy before switching app services.

Preserve the existing rollout gates: server `MICRONUTRIENT_IMPORT_ENABLED=false`
and `XOT_COACHING_ENABLED=false`, mobile
`EXPO_PUBLIC_MICRONUTRIENT_SYNC_ENABLED=false`. The expanded supplement editor
and confirmed fixed-nutrient writeback ship; the wider 27-category native
collection/bound-custom-nutrient adapters remain disabled in this release.
Enabling them requires their separate native permission/receipt acceptance.
Do not describe the editor alone as verified magnesium export to Apple Health.

EAS preflight reports last production build **40**, with no Apple build 41 yet.
Use the normal cloud production profile with automatic submission from the
[TestFlight runbook](../../XoTMobile/docs/testflight-release.md). Preserve 1.7.2,
all bundle/app-group IDs and signing settings. A guarded private launcher starts
cloud build/upload and production deployment in parallel. It pins the source,
checks the expected previous number and records an attempt before submission;
it never starts a second upload while one is pending.
