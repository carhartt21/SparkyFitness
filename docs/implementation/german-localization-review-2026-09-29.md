# German localization review — 2026-09-29

Scope: active German mobile and web catalogs, iOS permission text, the iOS widget, and rendered login, Dashboard, Diary, food search, Settings, and upstream-release surfaces. Review data came from the isolated synthetic demo and iOS review transport. Imported/user-entered names and upstream release notes were treated as source content, not interface translations.

The German mobile catalog has 4,970 of 4,970 active source keys, with seven stale Weblate keys. Structural completeness does not imply linguistic completeness. The new scan is deliberately heuristic: it cannot judge grammar, medical meaning, all hard-coded JSX, or provider/user text. The rendered review covered representative screens rather than every route and state. English names in synthetic food/workout records remain literal. The global brand substitution in `SparkyFitnessFrontend/src/i18n.ts` can still obscure legitimate upstream attribution elsewhere and merits a separate source-aware review.

Validation: `node scripts/apply-german-overrides.mjs --check`, `node scripts/audit-german-copy.mjs`, `node --test scripts/audit-german-copy.test.mjs`, mobile `i18n:generate:check`, `i18n:audit`, `native-locales:check`, `typecheck`, `lint`, `knip`, and `format:check`, plus web `typecheck`, `lint`, `knip`, `format:check`, and a direct Vite production build. The package `npm run build` wrapper could not run because `pnpm` is absent from this machine; its constituent checks and Vite build passed separately. The 390×844 German iOS review passed its render smoke and native food-entry interaction flow using synthetic in-memory data. A 430-point accessibility-extra-large German Dashboard render smoke also passed; the page remains vertically scrollable. The dark German web demo was checked at 1280×800 and 390×844 for Dashboard, Diary, and Settings; these captures had no horizontal page overflow. A fresh `de-DE` browser context showed the German login form and success toast, and detection checks retained `pt-BR` while mapping `en-US` to `en`. This does not validate production persistence or every language setting.
