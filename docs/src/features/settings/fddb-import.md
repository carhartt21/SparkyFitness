# Import an FDDB account export

In **Settings → Data Import → FDDB account export**, choose the complete account CSV. X on Track parses it in the browser and first shows the sections and date range. Profile fields, transaction records, and image references are excluded from the requests. The source CSV remains on your device unless you explicitly upload it elsewhere.

The diary step sends food entries in batches of 100. Each entry keeps its local date and time, logged energy and macronutrients, and original occurrence. FDDB supplies energy in kilojoules; the importer converts it to kilocalories using 4.184 kJ/kcal. It does not infer energy from macros or overwrite foods already in the library. Because the FDDB export has no meal category, imported rows appear in a dedicated **FDDB Import** diary group. A row reported as `0 g` or `0 ml` with nutrition is retained as a one-serving snapshot with its original label, rather than claiming a measured mass. Retry a stopped import from the same preview; importing the same file again skips its existing source IDs. Entries previously imported through a different source are not automatically merged, so inspect any overlapping history before restoring the diary.

The last step is optional and initially deselected. You can review and select custom foods, saved recipes, favorites, weight measurements, and activity records. Custom foods become private per-100 g foods. Available caffeine and alcohol values are retained; FDDB's water mass is not treated as measured drinking volume. Recipes become private drafts containing the exported ingredient text; their nutrition is **not** calculated until ingredients are linked and reviewed. Favorites are linked only when an owned food has one exact name match. Existing weight readings on the same date are preserved; an empty weight field can be filled without replacing other check-in values. Activity records should be selected only after checking for overlaps with another exercise or Health sync source; they are not complete workout sessions.

The import does not restore FDDB social data, profile details, transactions, or images. Importing into another user's account through family sharing is disabled. The original export is not checked into the repository; parser tests use synthetic rows.
