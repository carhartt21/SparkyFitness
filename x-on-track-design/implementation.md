# X on Track progression identity

The four unchanged supplied raster references are in `references/`. The SVG masters in `../assets/brand/` and the application PNGs are generated from `shared/src/brand/progressionX.geometry.json` by `node scripts/generate-progression-x.mjs`. This JSON is the single source for the mark's geometry, segment order, color stops, baseline colors, and paths used by both progress components. The standalone full and empty drafts determine the outline and crossing; the dashboard mockups guide surfaces and hierarchy. Their sample dates, values, tagline, goals, and promotions are not product data.

The canonical mark has five overlapping paths inside a 320 × 320 viewbox: four rounded outline segments and one filled, tapered diagonal sweep. The sweep is drawn last so its crossing remains continuous. The source drafts have small raster asymmetries, so this vector fixes one geometry for full, empty, partial, and unknown states. Gradients stay anchored to the full paths; only the progress mask's measured arc length changes. The generated static SVG adds a separate, subtle glow layer and border for large brand placements. Dynamic components omit that decorative glow to stay crisp at small sizes.

The SVG master was refined against both standalone drafts. Its rounded frame now uses the references' inset and shorter height, the empty state has a neutral dimensional slate treatment, and the full state uses a warm lower-left border, localized green wash, brighter lower-right path, and separate soft and wide bloom layers. The path silhouette and center sweep stay identical in every state. `review/progression-x-full-comparison.png` and `review/progression-x-empty-comparison.png` place the source raster on the left and the generated SVG on the right at equal size. The original JPEGs contain photographic glow and texture, so their pixels cannot be reproduced exactly by scalable vector shapes; the canonical geometry and visually meaningful color relationships are preserved.

`BrandMark` is static and fully lit. `ProgressTrackX` takes a single number or unknown value, a label, and an unknown label. It is used for completed/planned sets in live workout headers on iOS and web. Zero keeps the whole graphite track visible; unknown dims that track and uses explicit unknown text. Invalid non-finite input is unknown; finite out-of-range input is clamped to 0–100. The web component interpolates from its current rendered value on retargeting; the mobile component stops its running animation and continues from its stopped value. Reduced-motion settings skip interpolation. Corrections may decrease the value.

The energy ring remains a conventional ring because calorie allowance is not a measure where “more is better.” No aggregate health score drives the static header mark. Live-workout progress uses actual completed sets divided by planned sets; no planned sets is unknown. The color spectrum describes distance along the logo's path, not health quality.

The mobile dashboard keeps its existing date, food, scan, hydration, workout, and recent-entry flows. The web keeps its existing route permissions, search destination, account controls, logging dialogs, widgets, and movable dashboard. The sidebar appears at 1280 px and above; smaller tablet layouts keep horizontal navigation and narrow web keeps the mobile navigation. Diary widget thresholds account for the sidebar's 248 px width, keeping two summary cards at 1280 px and three at 1440 px. Quick actions use real existing flows. Web hydration no longer substitutes an invented 1,920 ml goal when none loads. Visible brand copy and web metadata use the new core line, “Whatever your X, keep it on track.”

Synthetic simulator screenshots are in `review/`; names indicate width/theme/scenario. They are not personal account data. The 390 and 430 captures were compared with `references/progress_x_mockup_dashboard.jpg`: the centered energy summary, quick actions, accent colors, metric hierarchy, and dark surfaces are present. Deliberate departures include restrained glow, a date-first header consistent with the prior approved header direction, the existing scrollable stacked hydration and exercise cards, and the existing bottom navigation destinations. The mockup's calorie arithmetic, suggested goal checks, motivational copy, and promotions were not copied.

Web screenshots requiring authenticated data are unverified because no disposable preview account is available. A physical-device installation, Watch/widget rendering, and a native release build are also unverified for this branch. The simulator captures verify layout rendering, not persistence or backend integrations. The new light mark asset was visually inspected, but the post-change light dashboard capture remains unverified because the preview harness rendered the dark theme for that scenario.
